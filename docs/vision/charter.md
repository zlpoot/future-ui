# 产品章程 · 现有 UI 库语义适配方向

日期：2026-10-05。负责人已确认产品方向；以下结构是后续设计依据，具体公开 API、首库版本与实现仍通过 #2/#3 和目标 Issue 确认。本次只整理文档与计划。

## 1. 初衷

负责人在 Mac mini 上维护 Model Hub、bilibili docs、MV 制作等多个工程。AI 生成的界面各自可用，但同类界面经常出现不同约定：一个弹窗有关闭按钮，另一个没有；按钮位置、表单间距和 pending 表达也需要反复提醒。

要解决的不是 AI 能否开发前后端，而是：在不同工程、不同开发轮次中，AI 能否基于现有 UI 库稳定沿用同一套产品约定，并让应用具备机器可理解的结构。

## 2. 一句话定位

**future-ui 是面向 AI 的跨 UI 框架语义与适配层：连接现有 UI 库，将组件、状态、交互和项目设计约束组织为统一的 machine-readable Contract，并向 Coding Agent 与运行期 Agent 输出分层、稳定的接口。**

“跨 UI 框架”区分两种替换：shadcn/Ark/MUI 等组件库替换，及 React/Vue 等渲染框架替换。共享语义不承诺全部 API、页面源码或视觉像素可直接互换。

## 3. 负责什么、不负责什么

| 负责 | 不负责 |
| --- | --- |
| 接入现有 UI 库，声明映射、版本、支持子集与差异 | 重新实现完整 Button/Dialog/Input 组件体系 |
| 把组件语义与项目默认约定变成可查询、可复用的数据 | 只维护一段“请保持样式一致”的长提示词 |
| 输出组件定义、受控页面实例结构、明确的诊断 | 自动理解任意 UI 源码或 DOM 的全部意图 |
| 从显式 Capability/handler/Binding 投影运行期工具 | 把任意按钮或 click 自动推导成业务工具与授权 |
| 保留可替换的主题、组件库和协议适配方向 | 新建通用 Agent Loop、事务控制平台或模型训练系统 |

现有原生参考组件可作为契约测试资产继续保留，但不是新的产品扩张目标，也不是第三方库适配已经完成的证明。

## 4. 五条产品原则

### 适配优先

真实渲染继续使用已安装 UI 库及应用自己的代码。优先正常 import、显式注册与最薄的必要封装；不能为了生成统一结构而强迫全项目迁移到新 DSL。

### 组件语义与项目政策分开

Component Contract 描述组件固有能力与可访问性义务；Library Adapter 描述上游实际怎样兑现；Project Profile 描述本组工程统一的 token、变体、组合和交互约定。不同项目可以选不同 Profile，不能把一位用户的所有设计偏好写进全局组件语义。

Profile 中的规则要有适用场景和显式例外。例如普通编辑弹窗要求关闭入口，与明确的阻塞流程可以采用不同规则；不是无条件要求任何 modal 都可随时关闭。

### 一致性可验证

规范说明、适配组件的默认行为、有界校验共同发挥作用。metadata 宣称 closable 不证明实际有关闭入口；声明通过、渲染通过、交互通过分别记录。超出适配/检查范围报告 unknown/not covered，不能给全站 PASS。

### 同源数据、不同投影

“IR”仅指既有 Contract 与实例/Profile 数据的统一视图，不新增与现有 Schema 竞争的事实源。开发期目录回答“怎么开发”；页面实例结构回答“当前受支持 UI 是什么”；显式业务工具回答“允许请求应用做什么”。这三者不能混用。

### 先真实工程，后扩大

先一个库、三种代表组件、一个编辑弹窗；再在第二工程复用同一 Profile；随后用第二个实际 UI 库做小范围语义对照。没有真实消费者，不为潜在功能加包、加接口或加实验。

## 5. 视觉统一的边界

future-ui 不另造一套视觉组件，但可以将共享设计 token、变体和布局规则映射到现有库。只有 token 名称相同不够：md、spacing、radius 等需要共享实值或明确映射。不同库若存在视觉差异，分别报告语义一致与视觉差异；不承诺自动像素一致。

## 6. 保留的四种使用方式

UI-only：适配与项目规范不要求 Agent/模型 SDK。
Agent-only：旧页面不换 UI，也可接显式业务能力。
组合：人和 Agent 通过可选 Binding 复用同一业务 action。
替换：只在明示支持子集内更换库、渲染框架、主题或协议，不兼容时明确诊断。

## 7. 第一版成功标准

同一版本 Profile 被两个真实工程引用。AI 能发现已安装组件、真实 import、示例、语义和限制；普通编辑弹窗的标题、关闭入口、操作区和处理中行为不再各自随意实现；遗漏能在受支持范围被发现。一个已接入页面同时可输出机器可读实例结构。

不以模型优效、复杂任务增益或统计不劣为当前前置条件；核心功能正确仍是底线。人工纠正次数、规范遗漏数、版本漂移与接入成本作为产品观察，不编造基线数字。

## 8. 历史、范围与协作

CAL-001 是已报告的配置级 toolchain-isolation pilot，原任务与 null/negative 结果保留，不改判成新路线的成功证明。大规模 acceptance、通用 patch/rollback 系统、全框架全组件、插件市场、真实支付、部署与发布均不在本阶段。

future-ui 位于能力供给侧，WebSkill 可在未来消费其明确接口；双方不强依赖，本轮不修改其他仓库。工程事实在 GitHub，Notion 仅留解释；具体后续计划见 [development.md](../exec-plans/development.md)。
