# 快速开始（Windows PowerShell）

从本 SDK 解压到完全新建的 React 工程，全程**不依赖 Future UI 源码仓库、workspace 或绝对路径**。

假设你已经解压 SDK，得到目录 `future-ui-react-sdk-0.1.0-rc.1`（下文以 `<SDK_DIR>` 代替它的完整路径；命令中的 `<SDK_DIR>` 与 `<YOUR_APP>` 请替换为你的实际值）。

## 0. 环境检查

```powershell
node --version      # 必须 >= 24.21.0
npm --version       # 建议 11+
```

## 1. 用 CLI 归档创建新工程

本 SDK 的 `create-future-ui` 是本地候选 CLI（未发布 npm）。用 `npm exec` 指向 SDK 内的 tgz 即可（等价 `npx --package=<tgz>` 方式，已实测）：

```powershell
cd <你的工作目录>

# 创建工程：<YOUR_APP> 是工程目录名（同时作为 package.json 的 name）
npm exec --yes --package="<SDK_DIR>\packages\create-future-ui-0.1.0-rc.1.tgz" -- create-future-ui <YOUR_APP> --local-rc-dir "<SDK_DIR>\packages"
```

参数说明：

- `<YOUR_APP>`：目标工程目录名，必须不存在或为空目录（已存在且非空会拒绝，不会覆盖文件）。
- `--local-rc-dir <dir>`：指向 SDK 内的 `packages/` 目录，必须包含四个 RC 归档：
  `future-ui-contracts-1.0.0.tgz`、`future-ui-react-provider-0.1.0-rc.1.tgz`、
  `future-ui-theme-0.1.0-rc.1.tgz`、`future-ui-shadcn-adapter-0.1.0-rc.1.tgz`。

生成结果：

- 四个 RC 归档被拷贝到 `<YOUR_APP>/vendor/future-ui/`，依赖改写为 `file:` 相对引用，
  与 monorepo / 源仓库路径无关。
- 模板包含 `src/`（React 入口 + 最小 demo）、`ai/`（AI 规范命令）、`AI-AGENTS.md`、
  `vite.config.ts`、`tsconfig.json` 等。

## 2. 安装依赖

```powershell
cd <YOUR_APP>
npm install
```

- 首次安装时 npm 可能询问是否批准 esbuild 的安装脚本（`esbuild@0.28.2`），执行：

  ```powershell
  npm install-scripts approve esbuild
  ```

- 安装需要网络获取公共三方依赖（React / Vite / Tailwind / Radix 等）；
  本 SDK **不包含完整 node_modules**，不是断网安装包。

## 3. 运行

```powershell
npm run dev
# 默认 http://localhost:5173 （仅 loopback 本地开发）
```

打开页面可见模板最小 demo：ShadcnButton、ShadcnTextInput、EditDialog 编辑弹窗、右上角 Light/Dark 主题切换按钮。

## 4. 常用命令

```powershell
npm run typecheck   # TypeScript 严格检查（tsc --noEmit）
npm run build       # Vite 生产构建（产物 dist/）
npm run test        # jsdom fixture 测试（vitest run）
npm run ai:view     # 输出当前工程 AI 规范视图（JSON）
npm run ai:doctor   # 检查依赖/版本/browser 入口一致性
npm run ai:check    # 对 src 组件使用做只读验证
```

## 5. 生产构建与预览

```powershell
npm run build
npm run preview     # 预览构建产物
```

## 6. 最小验证清单（新工程收到即应通过）

```powershell
npm run typecheck   # 退出码 0
npm run build       # 退出码 0
npm run test        # 模板 fixture 通过
npm run ai:doctor   # 无诊断（JSON 中 diagnostics 为空）
npm run ai:check    # 无诊断
```

以上每一条都有对应退出码：非 0 即失败，JSON 输出会给出 diagnose 说明。

## 常见问题

| 现象 | 处理 |
|---|---|
| `npm install` 报 `404` 或找不到 `@future-ui/*` | 工程是用 registry 引用生成的（未带 `--local-rc-dir`）或归档未进 `vendor/`；用 SDK 内 CLI + `--local-rc-dir` 重新生成 |
| `npm install` 卡在 esbuild 脚本 | 执行 `npm install-scripts approve esbuild` 后重试 |
| `npm run dev` 端口被占用 | 模板默认 5173；被占用时 Vite 会自动换端口，以终端输出为准 |
| 编译报 `Cannot find module '@future-ui/...'` | 确认 `vendor/future-ui/` 四个 tgz 存在且 `package.json` 的依赖为 `file:vendor/future-ui/...` |
| 深色模式下 Dialog 文字看不清 | 见 `docs/主题与样式.md` 的“Dialog 深色文字继承陷阱”小节（应用层补一行 CSS） |
