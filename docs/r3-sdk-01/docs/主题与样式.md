# 主题与样式

Future UI 主题的单一数据源是 `@future-ui/theme/theme.css`（Light/Dark token）。
消费端只需要三步：导入 CSS、让 Tailwind 扫描适配器产物、用 `<html data-theme>` 切换。

## 1. 引入 theme.css

在工程的入口样式（模板为 `src/styles.css`）顶部导入：

```css
@import "tailwindcss";
@import "@future-ui/theme/theme.css";
```

## 2. Tailwind CSS v4 显式源扫描（必做）

shadcn-adapter 打包产物里的组件类名（`bg-primary`、`text-foreground`、`border-border`、
`bg-background`、`placeholder:text-muted-foreground` 等）位于 `node_modules`，
Tailwind v4 默认自动扫描**不会覆盖**，必须显式声明 `@source`：

```css
@source "../node_modules/@future-ui/shadcn-adapter/dist";
```

缺少这行会导致编辑弹窗等组件在构建产物中样式缺失（页面能渲染但无样式）。

## 3. Light/Dark 切换

token 定义在 `:root / [data-theme='light']` 与 `[data-theme='dark']` 两组选择器上。
切换只需同步 `<html>` 的 `data-theme` 属性：

```tsx
// 模板自带 useHostTheme：切换只改 data-theme，不复制任何色值
const [themeName, setThemeName] = useState<'light' | 'dark'>('light');
useEffect(() => {
  document.documentElement.setAttribute('data-theme', themeName);
}, [themeName]);
```

关键 token（light / dark 真实值，来自 theme.css）：

| token | light | dark |
|---|---|---|
| `--future-ui-bg`（background） | `#ffffff` | `#0b1220` |
| `--future-ui-surface` | `#ffffff` | `#101a2c` |
| `--future-ui-text`（foreground） | `#1a1a1a` | `#e6edf7` |
| `--future-ui-muted`（muted-foreground） | `#555555` | `#8fa3bf` |
| `--future-ui-border` | `#e2e8f0` | `#2a3a56` |
| `--future-ui-primary` | `#0f172a` | `#3b82f6` |
| `--future-ui-focus`（ring） | `#2563eb` | `#60a5fa` |

组件类名通过 Tailwind `@theme inline` 映射到这些 token：`bg-background`、
`text-foreground`、`border-border`、`bg-primary`、`ring-ring` 等。

## 4. Dialog / Portal

Radix Dialog 渲染在 `body` 外层 Portal。token 写在 `<html>`（`:root`）上，
因此只要 `data-theme` 在 `<html>` 上，**Portal 内 Dialog 会自动随主题换肤**；
不要只把 token 写在某个业务容器上。

主题切换按钮建议用 `fixed` + `pointer-events-auto`（模板 `ThemeFloatToggle` 即如此），
保证 Dialog 打开期间仍可物理点击换肤。

## 5. 已知陷阱：Dialog 深色文字继承（真实缺陷，消费端需处理）

**现象**：dark 主题下，Dialog 背景由 `bg-background` token 变为深色（`#0b1220`），
但 vendored shadcn Dialog/Input 的冻结类**不包含 `text-foreground`**，
内部文字/输入在 light 下依赖默认黑色继承（正常），dark 下就会变成**黑字深底，不可读**。

**原因**：这是上游 vendored 冻结样式（未随主题切换前景色）的表现；适配器不修改冻结源码。

**消费端修复**（应用层一行 CSS，不改组件/契约）：

```css
/* 在你的 src/styles.css 末尾追加 */
[role='dialog'],
[role='dialog'] input {
  color: var(--color-foreground);
}
[role='dialog'] input::placeholder {
  color: var(--color-muted-foreground);
}
```

修复后实测：light 白底 `#ffffff` + 文字 `#1a1a1a`；dark 深底 `#0b1220` + 文字 `#e6edf7`，
可读性正常。

## 6. 验证

```powershell
npm run dev          # 打开页面
# 打开 EditDialog，点右上角“切换到深色/浅色”，确认 Dialog 与页面同步换肤
npm run ai:view      # 输出中 Light/Dark 主题约定（theme 字段）
```
