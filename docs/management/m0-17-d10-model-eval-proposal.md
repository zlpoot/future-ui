## 1. 背景与定位

#23 是 #13（AI-first 开发闭环）下的真实模型评估子项：以**冻结的任务集和预算**对比两组——基线组「直接 Ark UI + 可用官方资料/工具」vs 实验组「future-ui 契约/目录/校验/patch/preview/test 确定性闭环」——在代表性前端开发任务上的开发效果。目的不是证明「AI 更强」，而是对 future-ui 工具链的**边际收益做可复现测量**。

前提：实验组可用 `catalog → validate → patch → preview → test`（#22/#25 已合并），共享业务动作族用 #10 的 cart 纵向示例。

## 2. 对照设计（公平性控制）

| 维度 | 冻结规则 |
| --- | --- |
| 模型/版本 | 同一模型、同一版本、同一温度/采样参数，两组一致 |
| 推理预算 | 两组相同的每任务 attempt 上限（默认 5）与 token 上限（默认 150K tokens/run） |
| 初始上下文 | 两组相同的任务说明模板；实验组额外注入 future-ui 工具链入口（不含人工逐步指导） |
| 环境 | 同仓库基线（main @ 批准时 SHA）、同 Node/pnpm 冻结版本、同浏览器/文档快照 |
| 任务说明与允许工具 | 逐任务冻结；两组措辞一致，仅工具集不同 |
| 顺序/泄露 | 适用时随机化组顺序；同一任务不跨组泄露答案 |

## 3. 任务集（首批冻结 4 个代表族）

| 族 | 任务样例 | 主要验证通道 | 依赖 |
| --- | --- | --- | --- |
| T1 创建合法表单 | 用 Button/Select/TextInput 搭表单并满足契约与交互语义 | schema 校验 + `ui.test` 结构/交互 | #6/#22/#25 |
| T2 修复无效组合 | 给出含非法 props/结构的代码，修复至契约合法且交互通过 | validate 诊断 + `ui.test` | #6/#22/#25 |
| T3 局部修改不伤及他处 | 修改指定区域（如 Select 状态/TextInput 受控），其他区域行为不变 | conformance 共享断言 + 回归 | #16–#21/#26 |
| T4 通过 preview/test 发现并修复交互问题 | 只给行为描述，让 AI 用 preview/test 定位并修复（如键盘激活、disabled 零事件） | `ui.preview` + `ui.test` | #25 |

可选扩展族（批准后追加）：T5 接入共享业务动作（cart，#10）；T6 更换主题（#20）；T7 异步错误处理；T8 可访问性修复。首批不含 T5–T8，避免预算与变量膨胀。

**成功判据（冻结于 acceptance 前）**：实验组不得只以 schema-valid 为成功；适用任务必须通过冻结的确定性 `ui.test` 交互断言。两组同判据。

## 4. 模型与版本建议

| 方案 | 模型 | 说明 |
| --- | --- | --- |
| 首选（推荐） | **Claude Sonnet 4.5**（或批准时最新稳定版） | 与主流开发 Agent 一致，工具调用稳定，成本适中 |
| 对比可选 | Gemini 2.5 Pro / GPT-5.x（择一） | 用于跨模型稳健性检查（额外预算档） |
| 成本参考 | DeepSeek-V3.x（国内可达） | 仅作成本参考，不作为主判据 |

控制变量：同一实验只用**一个模型**跑两组；多模型仅在扩展档并分开展示。模型版本与快照随报告记录 exact version。

## 5. Calibration 与 Acceptance 分离（硬规则）

1. **Calibration（pilot）**：每族 3 个样本 × 2 组（共约 24 runs），仅用于：验证任务说明可执行、测量任务难度与通过率基线、校准 attempt/token 上限与预算估算。
2. calibration 数据**不计入**正式 acceptance；不得用已看过的结果回填门槛。
3. calibration 结束后**冻结**：测量方法、任务集/样本量、阈值、停止条件、报告格式（写入本文件或 #23 更新版）。
4. **Acceptance**：每族 8–10 个独立样本 × 2 组（首波共约 64–80 runs），按冻结协议执行；修改关键方法/阈值须重新说明并重启受影响 acceptance。

## 6. 样本量与统计口径

- 首波 acceptance 样本量：4 族 × 8 任务 × 2 组 = **64 runs**（标准档）；扩展档 4 族 × 10 任务 × 2 组 = 80 runs/模型。
- 报告指标：首轮通过率、完成率、平均修复轮数、最终交互正确率（确定性 test 通过）、改动引发回归率、token/成本/时延、失败类别分布。
- 分层报告（按族/按组），保留所有尝试与失败样本；结果只在冻结任务集与样本量范围内解释，不做小样本泛称。

## 7. 模型预算建议（USD 估算，2026-10 主流定价）

| 档位 | 内容 | 估算 | 封顶 |
| --- | --- | --- | --- |
| 最小可行 | 1 模型 × 4 族 × 6 任务 × 2 组（48 runs）+ calibration 24 runs | $120–180 | **$200** |
| **标准（推荐）** | 1 模型 × 4 族 × 8 任务 × 2 组（64 runs）+ calibration 24 runs + 15% 缓冲 | $250–450 | **$500** |
| 扩展 | 2 模型 × 标准档（≈160 runs） | $500–750 | **$750** |

规则：
- 每 run 默认 ≤150K tokens；超限计为该任务 attempt 失败。
- **单日封顶 $150**，超限即停并汇报。
- 重试计入预算；预算用尽立即停止，不追加（追加需重新授权）。
- 费用按实际 provider 账单记账，报告附成本明细与汇率口径。

## 8. 停止条件

- 单任务：5 次 attempt 上限或 150K tokens 上限（先到为准）。
- 全局：预算封顶 / 单日封顶 / 连续 3 任务同失败类别无进展 / 环境不可复现。
- 结果无法在同一 main SHA 上复现 → 停止并升级，不回填。

## 9. 记录与报告

- 每次 run 记录：任务 ID、组别、模型/版本、attempt 次数、工具调用轨迹、`ui.test` 结果、token/成本/时延、最终判定与失败类别。
- 原始产物（含失败样本）提交至 `docs/management/m0-18-d10-results/`（或批准时约定路径），exact main SHA 可追踪。
- 结论分级：E1 确定性 jsdom / E2 真实浏览器 / E3 真实模型，分开记账，不互相替代。
